    <h1>Release history.</h1>
    <p class="document-intro">A concise record of what changed and what users can expect.</p>
    <section class="document-section version-row"><div class="version-number">0.1.8<br>August 5, 2026</div><div><h2>Release-candidate polish</h2><ul><li>The store-facing name is simply “Page Push,” with concise current-page language and an action tooltip that explains the click.</li><li>Product-facing pages hide implementation version numbers while the changelog and extension settings retain them.</li><li>The public product layout now flows cleanly on narrow mobile screens.</li><li>Store artwork matches the extension’s current delivery feedback.</li></ul></div></section>
    <section class="document-section version-row"><div class="version-number">0.1.7<br>August 5, 2026</div><div><h2>Toolbar language</h2><ul><li>The toolbar hover now reads “Push Page - Send anywhere.”</li><li>A check badge replaces the generic “OK” after a successful push.</li><li>The complete release version remains visible in extension settings.</li></ul></div></section>
    <section class="document-section version-row"><div class="version-number">0.1.6<br>August 5, 2026</div><div><h2>A language worth remembering</h2><ul><li>“Configure once. Push anywhere.” is now the shared product slogan.</li><li>Push is used consistently as the delivery verb throughout the extension.</li><li>The product directory now presents a broader collection of work rather than only small tools.</li></ul></div></section>
    <section class="document-section version-row"><div class="version-number">0.1.5<br>August 5, 2026</div><div><h2>One-click delivery</h2><ul><li>Clicking the configured toolbar icon now sends the current page directly.</li><li>Compact badges show sending, success, and failure without opening a popup.</li><li>Unsupported browser pages use the browser's muted extension state.</li><li>The full patch version is visible in settings.</li></ul></div></section>
    <section class="document-section version-row"><div class="version-number">0.1.4<br>August 5, 2026</div><div><h2>Clearer extension identity</h2><ul><li>Extension-list name now explains that Page Push sends pages to the user's API.</li><li>The product visual shows the simple direct path from the current page to the user's endpoint.</li></ul></div></section>
    <section class="document-section version-row"><div class="version-number">0.1.3<br>August 5, 2026</div><div><h2>Direct delivery polish</h2><ul><li>Long page titles remain readable in the popup.</li><li>Chrome Web Store placeholder links added while submission is pending.</li><li>Public product face now shows the direct browser-to-endpoint flow.</li></ul></div></section>
    <section class="document-section version-row"><div class="version-number">0.1.2<br>August 5, 2026</div><div><h2>Unified product mark</h2><ul><li>One larger push-to-endpoint mark across browser, release packaging, and the product site.</li><li>Improved legibility in browser's compact pinned-extension area.</li></ul></div></section>
    <section class="document-section version-row"><div class="version-number">0.1.1<br>August 5, 2026</div><div><h2>Presentation polish</h2><ul><li>Product website linked directly from the extension header.</li><li>Consistent product navigation and favicon across the product site.</li></ul></div></section>
    <section class="document-section version-row"><div class="version-number">0.1.0<br>August 5, 2026</div><div><h2>Initial release candidate</h2><ul><li>Manual delivery of the current HTTP or HTTPS webpage to one user-configured HTTPS API endpoint.</li><li>Optional selected text and referring URL context.</li><li>No authorization, bearer token, and custom-header receiver modes.</li><li>Copyable payload preview and test connection.</li><li>Explicit endpoint permission, delivery status, and useful failure messages.</li><li>No automatic capture, Page Push account, hosted backend, tracking, analytics, or AI.</li></ul></div></section>
